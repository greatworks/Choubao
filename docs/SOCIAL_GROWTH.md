# 《你个臭宝》分享增长与上线配置

## 已实现功能

- **同图踢馆**：通关分享携带关卡编号、用时、连击和失误数，接收者挑战完全相同的确定性布局。
- **残局接力**：失败分享携带已移除箭头编号，接收者直接从相同残局继续。
- **新手承接**：从高密度挑战进入的零进度玩家先完成第 1 关热身，再自动进入好友原局。
- **今日迷宫**：日期映射固定关卡，同一天所有玩家获得同一布局；当日首次通关可获得独立的 20 金币完成奖励，该奖励与分享无关。
- **动态分享卡**：运行时输出 500×400 PNG，展示真实关卡缩略图、用时或剩余箭头、玩家风格和品牌角色。
- **好友榜与提醒**：开放数据域显示微信好友关卡进度与今日用时，可主动申请被好友超越时的系统提醒。
- **官方擂台暂缓**：首发版本隐藏官方擂台入口，保留普通同图分享、今日迷宫和好友榜；待平台能力单独审核后再启用。
- **回流归因**：本地记录挑战打开、开局、完赛、发起分享和回敬分享；配置云开发后汇总好友尝试次数。

## “臭宝”文案系统

文案把“你个臭宝”当作角色对玩家、玩家对好友的亲昵称呼，而不是机械地重复产品名。语气遵循四个原则：先亲近再挑战、可以互损但不羞辱、失败时安抚并给出下一步、外发标题必须带完整名称“你个臭宝”。界面中的高频功能词保持简短，品牌称呼集中在首页行动、操作反馈、通关、失败、好友邀请和排行榜等情绪节点。

分享标题按真实场景选择，不做与本局无关的纯随机轮播：

- 第 1 关使用“你个臭宝，不会第一关都过不了吧？”，承担低门槛教学后的轻度激将。
- 指定高难关使用“90%的人卡在第 X 关”，上线后需根据真实通过率校准比例。
- 零失误高连击突出“一口气清空”，普通通关突出真实用时或能玩到第几关。
- 好友同图挑战完成后使用“反超了，敢再来吗”，形成一次分享后的回敬闭环。
- 失败残局使用“已老实，速来帮我”“这也太难了吧”，好友点击后直接接手相同残局。
- 今日迷宫突出“所有人同一张图”和真实用时，降低好友理解成本。

微信分享标题、分享卡短标题和卡片行动提示分别生成，避免把一整句长文案缩进 500×400 卡片。每套文案带稳定的 `copyId`，写入分享 query、云端挑战记录和打开、开局、完赛事件，用于比较不同文案的卡片打开率及挑战转化率。

## 合规边界

分享是玩家主动表达和发起挑战的入口，不影响通关金币、复活或下一关解锁。四种道具各有且仅有 1 次首次分享补给，玩家点击明确的分享按钮发起同图挑战后获得 1 次额度；页面可正常关闭，也不设置群人数任务、概率奖励或无法关闭的分享引导。“90%的人卡在这一关”是挑战型文案；上线后应依据真实关卡通过率校准，若数据不支持该比例，应改为“这团箭很难一次清空”。

相关实现遵循微信小游戏[分享能力](https://developers.weixin.qq.com/minigame/dev/guide/open-ability/share/share.html)、[关系链数据](https://developers.weixin.qq.com/minigame/dev/guide/open-ability/open-data.html)、[好友排行榜](https://developers.weixin.qq.com/minigame/dev/guide/open-ability/ranklist.html)、[排行榜提醒](https://developers.weixin.qq.com/minigame/dev/guide/open-ability/subscribe-system-message.html)和[平台运营规范](https://developers.weixin.qq.com/miniprogram/product/)。

## 云开发上线步骤

1. 在微信开发者工具开通云开发，复制环境 ID 到 `src/config.js` 的 `SOCIAL.cloudEnvId`。
2. 在云数据库创建集合 `choubao_challenges`，权限选择“所有用户不可读写”，由云函数访问；建议为 `owner` 建立单字段索引。
3. 在开发者工具中右键 `cloudfunctions/social`，选择“上传并部署：云端安装依赖”。不要选择仅上传文件，仓库不会提交 `node_modules`。
4. 真机从一台微信分享给另一台微信，验证邀请页关卡编号、目标成绩和残局状态一致。
5. 视后台能力配置并观察 `choubao_share_create`、`choubao_counter_share`、`choubao_challenge_open`、`choubao_challenge_start`、`choubao_challenge_finish` 事件。该项用于运营分析，不阻塞首发审核。
6. 新经济系统同时上报 `choubao_prop_intro_share`、`choubao_prop_ad_start`、`choubao_prop_ad_complete`、`choubao_revive_ad_start`、`choubao_revive_ad_complete`，用于计算首次分享补给触发率、道具视频完成率和复活视频完成率。
6. 在“游戏能力地图 - 微信排行榜配置”登记排行榜和分数键，确认 `cblevel` 已审核生效；首发不配置官方擂台赛。

`cloudEnvId` 留空时不会请求云函数，但分享 query 仍包含完成同图挑战所需的核心数据，因此本地预览和无云环境版本不会中断。

## 微信能力检查

- `game.json` 已声明 `openDataContext: "src/open-data"`。
- 微信排行榜键：`cblevel`，整数类型、降序、单位“关”。
- 玩家授权、小游戏回到前台、通关和打开好友榜时都会补写 `cblevel`；好友榜仅在进入时刷新一次，展示期间不轮询。
- 游戏内开放数据域还会读取今日用时键 `choubao_daily_best_ms`。
- `choubao_daily_speed` 为未来官方擂台预留键，首发不登记、不显示入口。
- 排行榜提醒必须由玩家点击按钮后请求，不能在启动时自动索取。接受 `SYS_MSG_TYPE_RANK` 后，代码会立即通过 `wx.setUserCloudStorage` 写入与后台配置一致的 `cblevel`；只有订阅成功且分数写入成功时，界面才显示“反超提醒已开启”。`wx.getRankManager().update` 仅作兼容补写，不影响标准提醒链路的成功判定。
- 玩家需要在当前排行榜周期内已有分数，并由好友首次反超才可能收到提醒；同一玩家每天首次被反超时由微信平台决定是否发送服务通知，发送时机与频率不由小游戏代码控制。
- 提审前使用两个互为微信好友的真机账号验证：A 开启提醒并停留在较低关卡，B 随后通关反超；两端都需使用线上体验版且完成隐私授权，后台排行榜键必须与代码完全一致。

## 隐私保护上线步骤

1. 在微信公众平台的“设置 - 服务内容声明 - 用户隐私保护指引”中，按实际能力声明“微信朋友关系”。
2. 为云开发补充自定义信息类型，覆盖云函数实际处理的用户标识、关卡进度、挑战成绩、好友挑战记录和使用事件；用途写明好友挑战、排行榜展示、进度同步与运营分析，保存期限和删除渠道按运营主体的真实制度填写。
3. 隐私指引审核通过后，开启平台提供的官方“隐私授权弹窗”。不要在 `game.json` 中添加非官方的弹窗间隔字段。
4. 启动和本地关卡不主动申请授权；玩家首次点击好友榜、排行榜提醒、激励广告等联网能力时，代码才调用 `wx.requirePrivacyAuthorize`。同意前不会初始化云开发、广告、数据上报、关系链排行榜或官方排行能力；拒绝后保留本地关卡与本地存档。
5. 玩家拒绝后再次进入上述联网能力时，可重新触发官方授权流程；设置弹窗底部以低权重文字保留“隐私保护指引”入口，并直接调用 `wx.openPrivacyContract` 查看微信平台登记版本。
6. 提审前在真机分别验证首次同意、首次拒绝、拒绝后重试、清除授权记录后重进，以及好友榜、挑战云数据和广告在同意前均无网络调用。

隐私指引的后台文字必须与当前代码和实际运营一致；后续新增头像昵称、手机号、定位、相册或客服表单时，应先更新声明并通过审核，再上线对应代码。

`wx-server-sdk` 固定为当前官方最新版 `4.0.2` 并提交依赖锁。其上游传递依赖仍存在 npm 审计告警，当前云函数不接受用户提供的 URL 或数据库字段路径，不应使用 `npm audit fix --force` 强制降级 SDK；后续升级前重新执行回归测试。

## 首发观测漏斗

1. 分享按钮点击率。
2. 分享卡打开到邀请页曝光率。
3. 邀请页到挑战开局率。
4. 挑战开局到完赛率。
5. 完赛后的回敬分享率。
6. 每个分享挑战带来的有效开局数。

没有任何机制能保证“无需推广即可爆火”。首发应先用真实数据验证卡片点击率和挑战承接率，再轮换文案、分享卡构图和目标难度；不要用提高分享频次来掩盖低转化。
